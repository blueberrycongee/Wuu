# 记忆

Memory 插件管理三种范围：**用户笔记本**保存关于你的长期偏好和反馈，**工作区记忆**保存
单个工作区跨会话仍有价值的事实，**会话记忆**保存当前任务的紧凑状态和草稿。它们都是普通
Markdown 文件，不是核心 Agent loop 的内建数据模型。

## 用户笔记本

用户笔记本保存跨会话仍有价值的个人偏好、反馈、参考信息和经验。它与某次会话历史不同，
也不应成为项目事实或临时任务日志的副本。

### 查看记忆

安装并启用一方 Memory 插件后，打开**设置 → 插件 → Memory**。这个设置页、记忆提示、
文件 Tool 和管理对话都由插件提供，宿主没有 `/memory` 专用命令或 Memory RPC。面板提供：

- 根据真实笔记本生成的概览；
- 刷新概览；
- 查看 `MEMORY.md` 索引和记忆文件原文；
- 用对话方式要求添加、修正或删除记忆，并查看实际变更文件。

概览由插件通过私有 Session 调用当前模型生成；需要立即反映原文变化时使用刷新。原文视图
才是审计记忆内容的直接依据。禁用或卸载 Memory 插件后，其页面、Tool 和提示会一起消失，
已有 Markdown 文件保留，重新启用时继续使用。

### 适合保存什么

- 长期沟通偏好；
- 用户明确给出的工作反馈；
- 跨项目仍成立的参考入口；
- 以后遇到类似问题仍有用的经验。

不要保存密钥、原始对话、短期任务进度、提交 SHA、一次性日志，或可以直接从当前仓库
重新获得的事实。

### 数据和模型调用

用户记忆默认位于 `~/.wuu` 下的记忆目录；设置 `WUU_HOME` 会整体移动 Wuu 的用户
状态。生成概览和通过对话修改记忆会调用当前模型服务，原文读取不需要模型。

记忆可能作为相关上下文发送给模型。处理敏感内容前，请同时检查记忆原文、模型服务的
数据政策和[安全模型](../reference/security-model.md)。

## 工作区记忆

启用 Memory 插件后，每个工作区有自己的 `project_memory`：Agent 在会话中通过插件提供的
`session_memory` 工具维护，
用于保存该工作区跨会话仍有价值的稳定事实。它位于工作区状态目录下的 `memory/MEMORY.md`，
与用户笔记本相互独立。

适合写入工作区记忆的内容：

- 架构决策和稳定约定；
- 长期有效的工作流经验；
- 跨会话需要继续使用的项目背景。

同一个插件 Tool 还管理会话级文件：`summary`（当前任务的紧凑可恢复状态）、
`checkpoint`（旧版兼容入口）、`notes`（会话草稿）。会话级内容属于单个活跃会话，
不应依赖它们在之后的会话中继续存在。核心只持久化普通 Session/Turn 历史，不会识别或自动
注入这些文件；模型按 Memory 插件的 Prompt 在需要时读取或更新它们。

## 后台记忆整合（Dream）

Dream 插件会在后台定期检查已完成会话，把值得保留的稳定事实整合进工作区记忆。它默认关闭，
可在**设置 → 插件 → Dream**中启用并调整运行间隔、候选数和模型别名。
Dream 通过 Memory 插件的 `session_memory` Tool 写回，因此禁用 Memory 后不会再获得这项写回能力。
触发条件、配置方式和限制见[后台记忆整合（Dream）](dream.md)。

## 与项目指令的区别

- `AGENTS.md`、`CLAUDE.md` 等项目指令持续影响工作区中的每个任务，适合随仓库共享；
- 用户笔记本保存用户的跨项目长期信息；
- 工作区记忆保存单个工作区的持久事实。

项目指令发现属于核心的通用 Prompt 输入，配置名是 `instructions`；旧版 `memory` 配置只在读取
时迁移。它不是 Memory 插件启停的一部分，也不会读取插件拥有的用户或工作区记忆文件。

## 记忆的信任边界

记忆内容会进入 Agent 上下文，可能影响它选择工具和处理文件。写入记忆的内容应来自
你自己确认的事实，而不是未经核验的第三方文本；发现记忆被污染时，在记忆面板中删除
对应条目。普通核心文件 Tool 不会把 `WUU_HOME` 当成通用可写目录，也不能直接绕过插件读写
用户、工作区或会话记忆；这些数据只能通过当前 generation 的 Memory 插件能力访问。协作命名
Agent 的身份笔记本是独立的协作状态，只在该 Agent 的显式文件范围内开放，不属于 Memory
插件的用户记忆接口。
