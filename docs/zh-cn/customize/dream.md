# 后台记忆整合（Dream）

Dream 是 Wuu 的后台记忆整合机制：在对话轮次结束后，它检查当前工作区的已完成会话，
把其中值得长期保留的稳定事实整合进该工作区的 [project_memory](memory.md#工作区记忆)。
它默认关闭，需要显式启用。

## 它解决什么问题

对话本身是短命的：会话结束后，其中做出的架构决策、发现的约定、学到的经验就留在
历史里，下次会话不会自动知道。Dream 在后台定期阅读已完成会话，把这类稳定事实写入
工作区记忆，让后续会话可以读到，而不是每次从头摸索。

## 开启与配置

在桌面端打开**设置 → 记忆**，可以：

- 启用或停用 Dream；
- 设置运行间隔（天）；
- 选择专用模型提供商和模型（留空则使用当前提供商和默认模型）。

也可以在用户配置 `~/.wuu/config.json`（或 `WUU_HOME` 下的 `config.json`）中配置：

```json
{
  "memory": {
    "dream": {
      "enabled": true,
      "interval_days": 7,
      "provider": "openai",
      "model": "gpt-4.1"
    }
  }
}
```

字段说明：

| 字段 | 含义 |
| --- | --- |
| `enabled` | 是否启用后台整合，默认 `false` |
| `interval_days` | 距离上次运行至少间隔多少天，默认 `1` |
| `provider` / `model` | 可选专用模型；留空使用当前选中的提供商和模型 |

通过桌面设置修改后会立即生效，下一次对话轮次结束就会按新配置检查；直接编辑配置文件
则需要重新启动 Wuu 才会加载。旧的 `memory.dream_interval_days` 字段仍被识别：正数
视为启用，`0` 视为停用；新配置优先。

## 什么时候运行

每次对话轮次结束后，Wuu 会检查一次是否满足以下全部条件：

- Dream 已启用；
- 距上次运行至少过了 `interval_days` 天（或从未成功运行过）；
- 自上轮整合以来有至少 5 个已完成会话。

满足条件时，整合在后台异步执行，不阻塞当前对话。同一时间只有一个整合任务在运行；
如果上一次运行失败，会等待约一小时再重试。中途崩溃留下的"运行中"状态会在超时后
自动修复并重试，不会永久卡住。

## 它做什么、不做什么

Dream 使用一个受限的后台 Agent，只配备：

- 只读工具：`read_file`、`list_files`、`glob`、`grep`、`thread_get`；
- 写工具：`session_memory`（仅 `project_memory` target）。

它通过 `session_memory` 追加或整理工作区记忆，不写会话级 `summary`、`checkpoint`
或 `notes`，也不修改工作区文件、不调用外部程序、不访问网络。整个任务有超时和
步骤数上限（约 3 分钟、最多 6 步工具调用）；没有值得保存的内容时它不会写任何文件。

## 隐私与成本

- Dream 会把已完成会话的文本发送给模型服务，并可能产生额外模型请求和费用；
- 专用模型可以避免与当前对话争用提供商，但也会产生独立的调用；
- 整合写入的工作区记忆与普通记忆一样会进入后续 Agent 上下文，处理敏感内容前请
  查看[安全模型](../reference/security-model.md)和记忆原文；
- 如果你不希望某类内容进入记忆，可以在记忆面板中删除对应条目；Dream 不会恢复
  被删除的内容。
