# 后台记忆整合（Dream）

Dream 是 Wuu 的后台记忆整合机制：在对话轮次结束后，它检查当前工作区的已完成会话，
把其中值得长期保留的稳定事实整合进该工作区的 [project_memory](memory.md#工作区记忆)。
它默认关闭，需要显式启用。

## 它解决什么问题

对话本身是短命的：会话结束后，其中做出的架构决策、发现的约定、学到的经验就留在
历史里，下次会话不会自动知道。Dream 在后台定期阅读已完成会话，把这类稳定事实写入
工作区记忆，让后续会话可以读到，而不是每次从头摸索。

## 开启与配置

安装并启用一方 Dream 插件后，打开**设置 → 插件 → Dream**，可以：

- 启用或停用 Dream；
- 设置运行间隔（天）；
- 选择可选模型别名（留空则继承当前 Session 的模型）。

设置保存在插件自己的工作区存储中，不再写入核心 `memory.dream` 配置。字段说明：

| 字段 | 含义 |
| --- | --- |
| `enabled` | 是否启用后台整合，默认 `false` |
| `interval_days` | 距离上次运行至少间隔多少天，默认 `7` |
| `min_sessions` | 触发前至少累计多少个完成 Session，默认 `5` |
| `model_alias` | 可选模型别名；留空继承父 Session |

通过插件设置修改后立即生效。禁用、升级或卸载插件会停止 Timer，不再产生后台唤醒；
重新启用后从插件持久化状态恢复候选、上次结果和失败退避。

## 什么时候运行

插件观察普通 Turn 完成事件，并由自己的 Timer 检查是否满足以下全部条件：

- Dream 已启用；
- 距上次运行至少过了 `interval_days` 天（或从未成功运行过）；
- 自上轮整合以来有至少 5 个已完成会话。

满足条件时，插件从最近完成的父 Session 创建一个 fork 私有 Session，再通过
`host.session.send` 投递整理 query，不阻塞当前对话。同一时间只有一个整合任务在运行；
如果上一次运行失败，会等待约一小时再重试。插件 generation 重启时会把未完成状态
收敛为失败，避免永久卡住。

## 它做什么、不做什么

Dream 的私有 Session 继承 fork 上下文，并通过 Memory 插件提供的 `session_memory`
读取和更新 `project_memory`。整理 Prompt 明确禁止保存密钥、原始对话、临时进度、PR 编号、
提交 SHA 或短期事实，也禁止修改工作区源文件；没有值得保存的内容时返回
`Nothing to dream`。核心不再拥有 Dream 的 Prompt、Tool 白名单、超时、步骤数或 AfterTurn Hook。

## 隐私与成本

- Dream 会把已完成会话的文本发送给模型服务，并可能产生额外模型请求和费用；
- 专用模型可以避免与当前对话争用提供商，但也会产生独立的调用；
- 整合写入的工作区记忆与普通记忆一样会进入后续 Agent 上下文，处理敏感内容前请
  查看[安全模型](../reference/security-model.md)和记忆原文；
- 如果你不希望某类内容进入记忆，可以在记忆面板中删除对应条目；Dream 不会恢复
  被删除的内容。
