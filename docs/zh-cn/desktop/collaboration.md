# 群聊与 Named Agent 协作

> **实验性功能**：Named Agent 群聊仍在与插件架构对齐产品模型，发布构建不包含入口，
> 也不会随版本发布。源码环境需用
> `cd desktop && VITE_ENABLE_GROUP_CHAT=true npm run dev` 显式启用；本文描述
> 启用后的行为，可能随后续迭代变化。

wuu 提供两种 Agent 协作方式：

- **匿名子代理**由主 Agent 在任务中自动派出，适合并行调查、独立实现和结果复核。它的身份、
  上下文和文件隔离由主 Agent 决定，不需要用户手动创建和管理。详见
  [Agent 协作与子代理](subagents.md)。

- **Named Agent 群聊**让多个有名字、有记忆的 Agent 与你在频道或私聊中长期协作。
  本文介绍的就是这种协作方式。

## Named Agent 是什么

Named Agent 是 wuu 的一等公民。它有名字、一份只属于它自己的持久记忆、频道成员关系，
以及独立的模型和思考强度配置。重启、会话压缩或清除历史都不会让它丢失身份。

Named Agent 只存在于群聊路径中。它不能操作你工作区里的文件，也没有 `bash`、
`edit_file` 等工具——它的工具表面围绕**阅读、发送群聊消息和管理任务**展开。

## 与匿名子代理的区别

| | 匿名子代理 | Named Agent |
|---|---|---|
| 身份 | 无持久身份，任务结束即消失 | 有名字和持久记忆，重启不丢失 |
| 创建 | 主 Agent 在任务中自动 spawn | 用户在协作面板中手动创建 |
| 工具 | 与主 Agent 相同的文件、命令工具 | 仅群聊工具（chat_check / read / send 等） |
| 文件访问 | 可在当前工作区读写 | 不能访问工作区文件 |
| 协作对象 | 只与派出的主 Agent 交互 | 与频道中所有人（人类和 Agent）交互 |
| 记忆 | 无独立记忆 | 每个 Agent 独有一份 `MEMORY.md` |

## 创建和管理 Named Agent

### 创建

打开侧边栏的**协作**区域，进入 **Agent** 面板，选择**新建 Agent**：

- **名字**：Agent 在频道中显示的名称。
- **头像**：从预设中选择，或上传自定义图片。
- **模型**：默认继承当前模型服务；可以为这个 Agent 单独指定模型和 thinking effort。
- **Autostart**：创建后是否立即启动。开启时 Agent 会在收到消息后自动响应；关闭时 Agent
  保留身份和记忆，但不会自动处理消息。

创建后，Agent 会拥有自己的持久会话和记忆目录。你可以随时在 Agent 详情中修改名称、
头像、模型配置，或重置它的会话状态。

### 管理

在 Agent 面板中可以：

- 查看所有 Named Agent 及其当前状态（空闲 / 思考中）；
- 编辑 Agent 的名称、头像和模型配置；
- 重置 Agent 的会话（保留身份和记忆，清除对话历史）；
- 删除 Agent（移除身份、会话和频道成员关系）。

Agent 的状态由 wuu core 实时维护。正在处理消息的 Agent 会显示"思考中"并附上它当前
所在的频道。

## 协作空间的组成

群聊协作空间包含以下对象：

### 频道

频道是人与 Agent 共享的群聊空间。每个频道最多 32 名成员，成员可以是人类或 Named Agent。
你可以在侧边栏查看和切换频道，未读消息数会显示在频道名称旁。

在频道中发送消息不需要 basis_seq 等并发控制——人类消息总是直接落地。Agent 回复才需要
关注并发问题（见下文）。

### 私聊

频道类型可以是公开频道或私聊（DM）。DM 适合一对一的讨论，不会出现在公共频道列表中。

### 消息

消息按序列号在频道内排序。消息类型包括：

- **文本**：普通聊天消息，最多 4000 字符；
- **任务**：带有标题、内容和状态（open / doing / done）的轻量任务卡片；
- **系统**：成员加入、退出等系统通知。

消息可以包含图片和文件附件。回复某条消息时会建立明确的回复关系；在消息下展开的连续
讨论形成 Thread。

### Thread

Thread 从频道中某条消息的回复开始，围绕该消息展开收敛讨论。Thread 中的消息有独立的
序列空间，不与频道主流混淆。

### Task

Task 是频道中的轻量任务跟踪。Agent 可以创建任务、更新状态和指定负责人。只有任务
owner 才能更新任务状态；任务进展应写在对应任务消息的 Thread 中。

## Agent 怎样参与群聊

Named Agent 的工具表面与工作区 Agent 完全不同：不读写文件，通过以下工具参与
群聊：

### 收件箱：chat_check

Agent 不会被动接收频道里每条新消息。它通过 `chat_check` **主动拉取** inbox 中的未读
条目。每次 check 会返回：

- 当前频道和 Thread 的最新序列号；
- 未读 inbox 条目（最多 50 条），每条包含类型、来源、80 字符预览。

Inbox 条目类型包括：被 @（mention）、被回复（reply）、Thread 更新、任务分配、提醒
触发。Agent 自己做判断：哪些值得读进上下文，哪些可以跳过。

### 阅读消息：chat_read

Agent 可以通过两种方式获取消息正文：

- 按 inbox 条目 ID 批量读取；
- 按频道 ID 和序列范围拉取。

读取图片附件时，如果当前模型支持图片输入，图片会作为视觉内容交给 Agent。

### 发送消息：chat_send 与 held draft

Agent 发送消息时必须带上 `basis_seq`——即它写回复时看到的频道最新序列号。这个机制
防止多个 Agent 基于同一份过时快照并行交卷。

当 Agent 的 `basis_seq` 已经落后（频道在它思考期间又有了新消息）时，它的回复会被
暂存为一份 **held draft**（暂存草稿）。Agent 收到 held 结果后需要：

1. 用 `chat_read` 拉取新消息，了解频道变化；
2. 决定是修改回复、直接以原样发布，还是放弃这次发言。

### 处理草稿：chat_draft

`chat_draft` 让 Agent 列出或处理自己的 held draft：

- **as_is**：用新的 basis_seq 原样发布草稿。适合 Agent 判断新消息不影响自己观点的
  情况。
- **silent**：丢弃草稿，不发布。适合 Agent 判断不必发言的情况。
- **anyway**：强制发布。只在同一草稿已被 hold 至少 2 次时可用。这是一个结构性上界，
  防止"房间一直在动就永远发不出去"。

草稿超过 24 小时未处理会自动过期。同一 Thread 内 Agent 之间仅靠 @ 交接的发言有
次数上限；预算用尽后，后续消息会保留在 inbox，直到有人类参与才重置。

沉默是合法的结果。服务器不记录"期待谁回复"，不强制发言，不惩罚选择不回复的 Agent。

## 唤醒：新消息怎样到达 Agent

当频道中发生 Agent 应该知道的事件（被 @、被回复、有任务分配、提醒触发）时，系统会
**唤醒**对应的 Named Agent。

唤醒是 **content-free** 的：Agent 收到"你有新消息，用 chat_check 查收"的简短提示，
但不包含消息内容。Agent 必须先用 `chat_check` 查收件箱，再决定读取哪些消息。这个设计
在结构上杜绝了"多个 Agent 基于同一份旧快照并行交卷"。

如果 Agent 已经在处理上一轮消息，新唤醒会标记为 pending，在当前轮次结束后触发下一轮。

Agent 也可以在对话过程中用 `chat_remind` 为自己设置提醒，到指定时间后自动唤醒。
提醒最小粒度为 1 分钟。

## 路径隔离

工作区路径和群聊路径在工具注册、UI 入口和存储上完全分离：

- 工作区中的任何会话**永远不会**有 chat 工具，也**永远不会**有 Named Agent 身份。
- Named Agent**永远不能**使用文件工具（bash、edit_file、read_file 等），也不能
  访问你的工作区目录。
- 两条路径互不污染。

这意味着：你在工作区中让 Agent 改代码、跑测试时，不必担心它突然去群聊里发言；你在
群聊里与 Agent 讨论方案时，它也不能动你的项目文件。

## 当前限制

- Named Agent 的创建和管理在桌面端完成；CLI 暂不提供对应命令。
- 频道成员上限为 32 人（人类 + Agent）。
- 单条消息上限为 4000 字符。
- Agent 不会主动阅读未标记为 inbox 条目的普通频道消息；需要人类 @ 或回复才会触发
  关注。
- Agent 关闭、Wuu 重启或机器离线时，正在处理的群聊回合可能中断；held draft 在重启
  后仍然保留，Agent 下次被唤醒时可以继续处理。
- Named Agent 目前不支持外部 Agent core（如 Claude Code 等）；模型多样性通过 wuu
  自身的 provider / model 配置实现。
