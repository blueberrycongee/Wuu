# Automations

Automations 让 Wuu 按计划在指定工作区中执行一段任务说明。它适合定时检查、周期性汇总
和稍后执行的一次性任务，不是独立运行的云端定时服务。

## 新建自动化

1. 安装并启用一方 Automation 插件，在桌面端选中任务所属工作区。
2. 从插件贡献的导航入口打开**自动化**。
3. 选择**新建自动化**，填写名称和任务内容。
4. 填写五段式 Cron 表达式和 IANA 时区，并选择是否重复执行。
5. 选择**创建**保存。页面会显示任务所属工作区；任务会显式记录工作区 ID 和根目录，状态、
   下一次执行时间和运行记录保存在该插件的工作区存储中。

任务内容就是每次触发时交给 Agent 的提示。应明确写出范围、期望结果和验证方式，例如：

```text
检查这个工作区中过去一天新增的 TODO。按文件汇总，只报告仍未解决的项目；
不要修改文件。如果没有新增 TODO，直接说明没有变化。
```

## 设置时间

当前插件直接接受五段式 Cron 表达式，例如 `0 9 * * 1-5` 表示工作日 9:00。时区使用
IANA 名称，例如 `Asia/Shanghai`；创建时默认采用系统时区。插件约每 15 秒检查一次到期任务，
因此触发时间允许有一个检查周期以内的延迟，不额外加入随机抖动。

## 选择会话方式

### 每次新建会话

桌面创建的任务使用 `new_thread`，适合彼此独立的检查。每次触发都会通过公共
`host.session.create/send` 在任务绑定的工作区创建一个新的用户可见会话，结果出现在该工作区
的普通会话列表中。App Server 会核对任务携带的工作区 ID 和根目录，避免投递到其他工作区。

### 继续指定会话

插件的 `cron` Tool 还可创建 `thread_heartbeat` 任务，把生成的普通 query 投递到已有会话。
这适合在同一上下文中持续跟进，但当前 Desktop 表单不直接编辑该模式。它有两个限制：

- 会话必须仍然存在并能在当前 Wuu 数据中加载；
- 如果该会话正在运行别的回合，自动化消息会排队，而不是并行写入同一会话。

## 管理任务

自动化列表展示任务内容、Cron、时区和会话模式，并支持暂停、恢复或删除。当前页面不提供
搜索、就地编辑或手动立即运行；需要变更任务内容时，删除后重新创建。

每个工作区最多保存 100 个自动化任务和最近 500 条运行记录。删除任务不可撤销，但不会
删除它已经创建或唤醒的会话。

当前桌面页没有“立即运行”按钮，也不展示单独的自动化运行历史。`新建会话`的结果会
出现在普通会话列表中；`继续指定会话`的结果写入目标会话。

## 运行条件和生命周期

Automations 由 Automation 插件 runtime 自己维护 Timer，不是 Wuu core scheduler。只有承载该
插件 generation 的 Wuu 进程正在运行时才会检查任务；禁用、升级或关闭插件时，宿主会等待
Timer loop 退出。电脑休眠或 Wuu 完全退出时，任务不会在后台执行。

- 错过的一次性任务会在调度器下次启动时补执行一次；
- 重复任务不会逐次补跑错过的时间点，多个漏跑会合并为下一次到期执行；
- 一次性任务执行后会从计划列表移除。

同一个计划时间点使用稳定的创建与发送请求 ID。即使同一工作区被多个 Wuu 进程短暂同时
加载，App Server 也会把重复请求收敛到同一个会话和回合，而不是重复执行任务。

新会话模式的每次到期都会创建独立会话；`thread_heartbeat` 使用核心的普通 Turn 排队和执行
租约，因此目标会话忙碌时会排队。插件目前不额外实现“跳过重叠运行”的产品策略。

任务使用执行时的模型、工具和权限配置。即使计划本身已经保存，权限限制、网络状态、
模型额度或工作区缺失仍可能让一次执行失败。

## 排错

### 到点没有运行

确认 Wuu core 当时正在运行，任务没有暂停，工作区路径仍然存在，并检查时区和列表中的
下次执行时间。到期任务由固定周期的后台检查发现，因此可能要等到下一次检查才会开始。

### 任务消失了

一次性任务运行后会移除。重复任务只有被用户/Agent 删除或插件状态损坏时才会消失。

### 继续会话失败

核对填写的是会话 ID 而不是标题，并确认会话没有被删除。若任务不依赖历史上下文，改用
`新建会话`通常更稳妥。

### 需要由 CI 或脚本触发

桌面计划任务适合本机定时执行。由外部调度器、CI 或其他 Agent 驱动时，使用
[`wuu exec`](exec.md)。
