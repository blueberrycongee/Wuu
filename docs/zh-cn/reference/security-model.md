# 安全模型

Wuu 是一个本地 Coding Agent。它会读取项目上下文，把选定的上下文发送给模型提供商，
也可以在用户的机器上运行工具。这些能力带来了实际权限，因此在 Wuu 中打开的仓库更应
被视为可执行代码，而不是被动文档。

本文说明 Wuu 当前的安全边界。模型输出仍需检查；操作系统级隔离需要使用容器、虚拟机或
独立的系统用户。

## 本地权限

Wuu 有三种权限模式：

| 模式 | 文件访问范围 | 修改能力 |
|---|---|---|
| `standard` | 已注册的工作区根目录 | 允许在这些根目录内修改 |
| `read_only` | 已注册的工作区根目录 | 禁止修改 |
| `unconfined` | 不受 Wuu 的工作区限制 | 可访问和修改当前系统用户有权操作的内容 |

默认的 `standard` 模式会在 Wuu 进程内执行路径限制和工具规则。获准运行的子进程会继承 Wuu 进程的系统
身份、环境变量和网络能力。路径边界和强制工具防护可以减少误操作，但无法抵御恶意
原生代码或已被入侵的依赖项。

`unconfined` 表示 Wuu 不再施加自己的路径边界。Agent 可以读取或修改当前系统用户有权
操作的内容，包括用户主目录、其他代码仓库和配置文件。专用文件工具仍会拒绝写入
`.env`、SSH 私钥和凭据配置等已知敏感路径，结构化 Git 工具仍会拒绝暂存或提交这些
文件；这些专用工具也会阻止直接访问 `~/.wuu` 中的应用凭据文件（`auth.json`、
`credentials.json`、`remote.json`、`phone.json`）。

这些是特定工具的纵深防护，不是所有执行路径都无法绕过的保证。任意 shell 命令、脚本和
子进程会继承 Wuu 进程的系统权限，可能绕过上述文件和 Git 限制。所有权限模式（包括
`unconfined`）都会继续对工具输出中的常见密钥格式做脱敏，但无法识别所有密钥或间接泄露
路径。

`unconfined` 使用当前登录用户的系统权限，仍会受到文件所有权和 ACL、macOS 隐私授权、
系统完整性保护、只读文件系统，以及可能存在的容器或系统沙箱限制。实际使用时，应把它
视为授予 Agent 当前用户级别的完整本机权限，只对可信任务启用。

在 `standard` 和 `read_only` 模式下，暴露完整环境、读取常见凭据路径、执行不安全
Git 操作，或者修改软件包和网络状态的命令，会受到额外的风险分类或强制检查。工具
输出也会对常见密钥格式做脱敏。这些措施属于纵深防御，不能保证识别所有密钥格式或
间接访问路径。

处理不信任的仓库时，请使用一次性虚拟机、容器或独立的操作系统账户。不要用权限模式
代替操作系统级隔离。

## 发送给模型提供商的数据

根据任务和启用的功能，Wuu 可能向已配置的模型提供商发送：

- 用户消息和对话历史；
- 系统提示词及适用的指令文件；
- 文件内容、搜索结果、diff、命令输出和工具错误；
- 已配置的用户记忆和工作区记忆；
- 用户添加的图片或其他附件；
- 返回给 Agent 的 MCP 或 hook 输出。

Wuu 不会有意把提供商 API Key 放进提示词。如果命令、hook、MCP 服务器、文件或用户
消息以未被识别的形式输出密钥，密钥仍可能泄露。请查看所选提供商的隐私与数据保留
条款。自定义 OpenAI 兼容地址会收到与其所替代提供商相同的提示词数据。

## 可信配置与项目输入

`~/.wuu/config.json`（或 `WUU_HOME/config.json`）中的用户配置是信任基础。正常
启动时，Wuu 会阻止项目替换提供商地址、凭据环境变量名、工作区外记忆路径、模型角色
或权限模式。`wuu exec --config` 和 `--ignore-user-config` 会显式信任所选项目配置，
适用于受控的自动化环境。

以下项目内容会影响 Agent 行为，使用前应进行检查：

- `AGENTS.md` 和其他自动发现的指令文件；
- `.wuu.json`、`wuu.json`、`.wuu/settings.json` 和本地设置；
- 项目 skills 和追加的提示词；
- hooks 和插件；
- `.mcp.json` 和原生 MCP 服务器配置。

项目 MCP 配置只有在本地设置中获准后才会加载。批准意味着信任该服务器或子进程访问
它能够获得的文件、环境变量、网络和凭据；MCP 输出本身也属于不可信的模型输入。即使
hook 和本地 skill 不执行原生代码，其中仍可能包含提示词注入。

## 凭据与本地状态

- 提供商密钥通常从 `providers.<name>.api_key_env` 指定的环境变量读取。
- macOS 桌面端把托管的 OAuth 凭据保存在钥匙串中；如果钥匙串失败，不会静默回退到
  明文文件。
- 无界面流程可以显式使用 `~/.wuu/auth.json` 和 `~/.wuu/credentials.json`（或
  对应的 `WUU_HOME` 路径）。Wuu 会把凭据文件设置为仅所有者可读写，但这不能替代
  操作系统钥匙串。
- 远程身份和已注册设备的数据保存在 `~/.wuu/remote.json`；手机凭据保存在
  `~/.wuu/phone.json`。这些文件同样仅限所有者访问，备份和分享时应按密钥处理。
- 会话、日志、工具结果、记忆和工作区状态保存在 `~/.wuu`。即使常见凭据格式已被
  脱敏，其中仍可能包含源代码和对话内容。

把 `~/.wuu`、环境文件、日志、会话导出或诊断包加入问题报告前，请先检查其中的内容。

## App server 与桌面端边界

`wuu app-server` 通过子进程的标准输入和标准输出使用逐行 JSON 请求/响应协议，本身不会打开网络
监听端口。Electron 客户端负责启动并管理该进程，通过 preload/IPC 桥向 renderer
开放选定操作。任何从 renderer 绕过 IPC 限制的方式或不安全的页面跳转都属于安全
问题。

## 远程与手机控制

`wuu relay` 默认监听 `127.0.0.1:8787`。绑定到其他地址会把服务暴露给对应网络，
此时操作者必须根据部署环境提供 TLS 和相应的安全控制。

远程主机会主动连接 relay，不会开放入站工作区服务器。手机通过限时配对链接注册。
已注册设备使用签名密钥认证，应用数据帧在主机与手机之间端到端加密。relay 只转发
不透明的数据帧和不含内容的推送提示，但仍能看到连接时间、设备在线状态、配对标识符
和网络地址。获得有效配对链接或手机凭据文件的人，可能以该设备身份注册或操作。

应把已配对手机视为拥有主机会话同等工作区权限的远程控制器。设备丢失或不再可信时，
请撤销其权限。

## 插件包

Wuu 插件从 `~/.wuu/plugins`、项目的 `.wuu/plugins` 和官方内置包发现。发现是惰性的：
已发现的包只是一份清单（manifest），在被激活之前不会执行任何代码。

激活由策略门控：

- 社区包只有在用户批准与其完全一致的包指纹后才会运行。指纹覆盖清单、可执行参数、
  hook 与命令定义、prompt 资产和 skill 目录树；任何变化都会停止激活并要求重新审批。
  批准、拒绝、禁用决策都是用户私有的，项目或共享配置无法设置。
- 官方内置包凭出处（随 Wuu 发布）获得信任，而不是凭清单文本。复用官方 id 的用户包或
  项目包无法遮蔽它。

权限来自封闭目录（`process.spawn`、`session.read`、`session.write`、`tools.define`、
`tools.intercept`、`shell.env`、`network.connect`、`commands.execute`、`files.read`、
`files.write`、`accessibility.read`、`accessibility.control`、`screen.capture`、
`app.activate`、`input.synthesize`）。目录外的权限名直接校验失败。宿主根据包声明的
能力面独立推导所需权限（运行时进程需要 `process.spawn`，MCP server 需要
`process.spawn` 和/或 `network.connect`，prompt hook 需要 `session.read` +
`session.write`），激活要求批准集覆盖完整推导集。

插件运行时进程通过 stdio 使用类型化 JSON 协议（`wuu-plugin-v1`）通信。宿主独立地把
每个协议 hook 映射到所需权限：`chat.message` 需要 `session.read`，`chat.request` 需要
`session.read` + `session.write`，`tool.definition` 需要 `tools.define`，
`tool.execute.*` 需要 `tools.intercept`，`shell.env` 需要 `shell.env`。插件声明了
未获批权限的 hook 会在初始化时被剥离，并作为诊断信息展示给用户；`session.start` 和
`session.stop` 只携带生命周期元数据，永远可用。插件进程只获得最小化的文档化环境
（PATH、HOME、临时目录、locale）——**不会**继承 Wuu 进程的环境变量，环境中的
API key 不会泄漏给插件。

撤销或变更批准后，插件进程会被关闭、其全部贡献被移除；被撤销插件注册的任何拦截点
都不会继续生效。

与本文其余部分相同的残余风险规则依然适用：获批插件是以当前 OS 用户身份运行的原生
代码。环境过滤和 hook 剥离防止的是误操作和未授权能力，它们不是操作系统级沙箱。
只批准你信任其代码的插件；对附带 `.wuu/plugins` 的项目，要像对待附带脚本的项目一样
谨慎。

## 安全使用检查清单

1. 为新仓库启用工具前，检查其中的指令、设置、hooks、skills 和 MCP 配置。
2. 批准插件前检查其请求的权限；包内容发生变化时需要重新审批。
3. 检查代码时使用 `read_only`；处理恶意代码时使用真正的操作系统级沙箱。
4. 把提供商地址和凭据环境变量名保存在用户配置中。
5. 私下完成远程设备配对；relay 跨越不可信网络时使用 `wss://`。
6. 发布改动前检查 diff 和命令输出。
7. 按照 [SECURITY.md](../../../SECURITY.md) 的说明私下报告边界绕过问题。
